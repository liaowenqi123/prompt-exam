# Prompt Exam · 提示词考试

朋友说他写的提示词比我好，说他是 Prompt 大师？这个世界还没有一个能测试提示词质量的东西——那就自己造一个。

**Prompt 考试局：老板丢给你一句话，你能不能把它变成一条好提示词？**

## 它是怎么工作的

1. 系统随机抽一道题——**题目就是老板的原话**：先给你一点点前情提要（你在什么公司、什么情况），然后老板丢一句永远讲不清楚的需求，比如"你给我设计一个网站"。
2. 你写一条**提示词**交给 AI。老板没说的地方（给谁看、干嘛用、什么约束、做成啥样算好）要你自己补上——**这是本题唯一的考点**。
3. 阅卷官（大模型）给你的提示词**主观打分 + 针对性点评**。不实际执行你的提示词，纯凭专业判断。

**动态体验**：交卷后同时发两个请求——**打分请求又快又小，先出分数**；**点评请求走流式输出**，文字实时蹦出来，绝不让用户干等。本地小模型默认关掉"思考过程"，出结果更快。

核心规则：题目不会自带答案，答案也不会从"让 AI 跑一遍"里漏出来——好提示词的本事就在于**补齐题面上没有的东西**，而且像真人说话一样自然、具体、有分寸。

## 评分标准（满分 100 分，考前不展示，考完才显示）

| 维度 | 分值 | 一句话 |
| --- | --- | --- |
| 接住意图 | 12 | 从老板一句话里抓住真正要什么，没跑偏 |
| 补齐题面 | 20 | 老板没说的地方，想到了多少、补上了多少（核心项） |
| 目标清晰 | 12 | 有没有把"做成什么样算好"讲清楚 |
| 指令具体 | 15 | 要求/步骤具体，AI 知道怎么下手 |
| 边界约束 | 10 | 别做什么、范围、限制说清楚没 |
| 自然像人 | 16 | 像真人说话，不机器腔、不生硬 |
| 语气分寸 | 10 | 语气跟任务搭，有温度、有分寸 |
| 具体落地 | 5 | 说人话能执行，还是空话套话 |

阅卷官会给出：总分 + 逐维度得分与理由 + 一段像朋友聊天、句句到位的**针对性点评** + 2~4 条马上能改的建议。

## 技术架构

- **前端**：React 18 + Vite（`web/`）
- **后端**：Node.js + Express 轻量代理（`server/`），把请求转发到任意 OpenAI 兼容的 `/chat/completions` 接口，并托管前端构建产物
- **阅卷模型**：只有一个（纯主观判卷、不执行）。**写死、用户不可修改**，默认本机 LM Studio 的 `qwen3.5-9b` 且关闭思考。想换模型改 `web/src/config.js` 里的 `JUDGE_CONFIG` 常量即可

> 为什么需要一个小后端？因为绝大多数大模型 API 不允许浏览器跨域直连。代理保持极简：不做鉴权、不落盘；前端把固定的模型参数随请求转发，后端只转发、不存储。

## 快速开始（本地开发）

```bash
npm install          # 安装根、server、web 三个工作区的依赖
npm run dev          # 同时启动后端(31337) 和前端(5173)
```

浏览器打开 http://localhost:5173 就能考。**模型不可由用户修改**，默认连本机 LM Studio 的 `qwen3.5-9b`。

### 阅卷模型（默认已固定）

- API 地址：`http://localhost:30001/v1`（本机 LM Studio）
- API Key：`lm-studio`（LM Studio 不校验）
- 模型：`qwen3.5-9b`（本地 9B）
- 「关闭思考」默认开启：qwen3.5 是思考型模型，不关掉会先在内心 OS 上耗光时间；关掉后打分、点评都是秒出

> 改模型/改地址：编辑 `web/src/config.js` 里的 `JUDGE_CONFIG`（部署时也可以由后端代理统一改写，前端不动）。
> 考试只做主观判卷、不执行提示词，谁用都花的是你这台电脑的算力。

## 部署

**方式一：单端口部署（推荐）**

```bash
npm run build        # 构建前端到 web/dist
npm start            # 后端同时托管前端，监听全部接口（IPv4+IPv6），端口 31337（可用环境变量 PORT 改端口）
```

把整个项目放到服务器上执行即可，访问 `http://<你的域名>:31337`。
不指定监听地址意味着本机和局域网内其它设备都能通过 `http://<本机IP>:31337` 访问，且 `localhost` 的 IPv4/IPv6 解析都正常。

> 端口说明：默认端口选了 **31337**。注意别用 6665~6669 这类端口——它们在 Chrome 的"危险端口黑名单"里，浏览器会直接报 `ERR_UNSAFE_PORT` 拒绝访问。
> 用 Tailscale 透传时：你本地电脑起的服务直接对公网服务器透传，阅卷模型就是你电脑上的模型（默认 `qwen3.5-9b`），谁用都花的是你本地算力。

**方式二：前端单独部署到静态托管（Vercel / Netlify / 对象存储等）**

只上传 `web/dist`，但此时需要配置 `web/vite.config.js` 的 `/api` 代理指向你部署的代理服务，或自行处理跨域。

### 模型配置（用户不可改）

- 阅卷模型写死在 `web/src/config.js` 的 `JUDGE_CONFIG`（默认本机 LM Studio `qwen3.5-9b` + 关闭思考），**前端没有任何模型配置入口**。
- 后端代理仍保留透传能力（接收 `baseURL / apiKey / model / disableThinking`），部署时如果不想改前端，可以直接在后端把请求统一改写到你的模型服务，前端代码不用动。
- 后端只转发、不存储、不落盘任何 Key。

## 项目结构

```
prompt-exam/
├── server/          # Express 代理后端
│   └── index.js     # /api/chat 转发 + 静态托管
├── web/             # React 前端
│   └── src/
│       ├── lib/scenarios.js   # 22 个"老板式"考题（前情提要 + 老板原话）
│       ├── lib/scoring.js     # 评分标准 + 阅卷提示词构造
│       ├── components/        # 首页 / 考试页
│       ├── config.js          # 阅卷模型配置（写死，用户不可改）
│       └── api.js             # 调用后端 /api/chat（含流式）
└── package.json     # npm workspaces（server + web）
```

## 常见问题

- **模型连不上 / 打分没反应**：确认本机 LM Studio 已启动并加载了 `qwen3.5-9b`（地址 30001）。
- **本地小模型偶发吐不出合法 JSON**：后端和前端都会自动重试纠正；仍失败会展示原始输出便于排查。
- **想换阅卷模型**：编辑 `web/src/config.js` 里的 `JUDGE_CONFIG`（改 `model`/`baseURL` 等），重新 `npm run build` 即可。
